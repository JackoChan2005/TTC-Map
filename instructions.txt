TTC Node API - Run Instructions

Quick start (recommended)

1) One-time setup, from the repo root
Windows: setup.bat
macOS:   ./setup.command
(creates the Python venv, installs Python + Node dependencies,
 writes PYTHON_BIN to node-api/.env.local so the server uses the
 venv, and runs the first data sync - takes a few minutes)

2) Start the server, from the repo root
Windows: start.bat
macOS:   ./start.command
(starts the server and auto-opens http://localhost:3000 in your
 browser once it is ready)

3) Stop Process
Control C


Manual run (if not using the scripts above)

1) Open terminal at node-api
*\TTC-MAP\node-api

2) Install dependencies (first time only)
npm.cmd install

3) Config files
node-api/env.config  = committed shared defaults (do not edit for
                       machine-specific values):
PORT=3000
NODE_ENV=development
DATABASE_PATH=../API/db/SubwaySystem.db
RT_DATABASE_PATH=./data/realtime.db
JSON_SOURCE=ckan-package:b811ead4-6eaf-4adb-8408-d389fb5a069c
CKAN_BASE_URL=https://ckan0.cf.opendata.inter.prod-toronto.ca
CKAN_FETCH_RESOURCE=false
GTFS_CHECK_INTERVAL_MS=21600000
NTAS_POLL_MS=30000
RT_SNAPSHOT_MAX_AGE_MS=90000
PYTHON_SYNC_ENABLED=true
PYTHON_BIN=python
PYTHON_SYNC_SCRIPT=API/src/update_db.py

node-api/.env.local  = your local overrides (gitignored). Any
variable set here wins over env.config. At minimum it should
contain PYTHON_BIN pointing at your venv interpreter - the setup
scripts create this file automatically:
PYTHON_BIN=C:\path\to\TTC-Map\.venv\Scripts\python.exe   (Windows)
PYTHON_BIN=/path/to/TTC-Map/.venv/bin/python             (macOS)

4) Start server
npm.cmd start

5) Open frontend
http://localhost:3000

6) Stop Process
Control C


What happens on startup

There are two databases, split by ownership:
- API/db/SubwaySystem.db     static GTFS schedule (written only by the
                             Python updater; Node reads it read-only)
- node-api/data/realtime.db  Node's own data: the realtime NTAS snapshot,
                             synced_records, sync_runs, meta

1) realtime.db initializes (created on first run)
2) Initial GTFS check runs once: the server compares the CKAN feed's
   metadata_modified against the version stored in the meta table and
   only rebuilds SubwaySystem.db when the feed changed (or the db or
   version marker is missing - e.g. on a fresh clone)
3) The GTFS check repeats every 6 hours (GTFS_CHECK_INTERVAL_MS)
4) The NTAS recorder polls realtime train positions every 30 seconds
   (NTAS_POLL_MS) and keeps exactly one snapshot row in realtime.db.
   The map serves that snapshot; if a poll fails or the snapshot is
   older than RT_SNAPSHOT_MAX_AGE_MS, the map immediately falls back
   to the schedule simulation (map-state responses show fallback:true)


API endpoints

1) Health
GET /api/health

2) Manual sync (GTFS check; add ?force=true to force a full rebuild)
POST /api/sync/run

3) Sync status (latest run)
GET /api/sync/status

4) List records
GET /api/records?limit=100

5) Get record by source key
GET /api/records/:sourceKey

6) Route search (used by frontend)
GET /api/route-search?route=1
GET /api/route-search?route=1&at=2026-02-13T05:00:00.000Z


Important notes for API calls

1) Route search requires the route query parameter
2) at is optional; defaults to current time if omitted
3) Route matching checks keys like route, route_id, line, route_number
4) Time matching checks keys like timestamp, updated_at, arrival_time, departure_time
5) If no matching route records exist, route-search returns 404


CKAN source note

1) Current package source syncs via package_show metadata
2) CKAN_FETCH_RESOURCE=false is intentional because this package's main resource is ZIP, not JSON
3) If CKAN_FETCH_RESOURCE=true, ensure selected resource is JSON/datastore data


Common troubleshooting

1) PowerShell blocks npm scripts
Use npm.cmd instead of npm

2) Port already in use (EADDRINUSE)
$env:PORT='3001'; npm.cmd start

3) Test sync quickly (only rebuilds when the GTFS feed changed;
   pass -- --force to force a rebuild)
npm.cmd run sync

Python sync integration (uses existing API/src/update_db.py)

1) The setup scripts (setup.bat / setup.command) handle all of this
automatically. The steps below are only needed for a manual setup.

2) Install Python deps once from repo root (inside your venv):
pip install -r requirements.txt

3) The committed env.config already enables the Python sync:
PYTHON_SYNC_ENABLED=true
PYTHON_SYNC_SCRIPT=API/src/update_db.py

4) Point PYTHON_BIN at your venv interpreter in node-api/.env.local
(gitignored - overrides env.config):
Windows: PYTHON_BIN=C:\path\to\TTC-Map\.venv\Scripts\python.exe
macOS:   PYTHON_BIN=/path/to/TTC-Map/.venv/bin/python
